# MAX DARK TUNNEL

تانل بین سرور **ایران** و **خارج**، با هسته‌ی اختصاصی Go (`mdt`) و منوی ساده.
همه‌ی حالت‌ها رمزنگاری‌شده‌اند و سمت خارج فقط با یک **Pair Code** راه می‌افتد. هیچ سؤالی، هیچ لایسنسی.

[English](README.en.md) · پشتیبانی: [@mikakhadm](https://t.me/mikakhadm)

---

## نصب

روی **هر دو** سرور:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/darktunnelmika/max-dark-tunnel/main/install.sh)
```

بعد از نصب، منو با دستور `maxdark` باز می‌شود.

## راه‌اندازی در دو قدم

**۱. سرور ایران:** منو ← `[2] New tunnel - IRAN`. اینجا نوع تانل و پورت‌های کاربر را انتخاب می‌کنی. آخر کار یک خط دستور با Pair Code تحویل می‌گیری.

**۲. سرور خارج:** همان یک خط را اجرا کن:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/darktunnelmika/max-dark-tunnel/main/install.sh) --pair MDT-xxxxxxxx
```

با همین یک خط، هم نصب انجام می‌شود، هم تنظیم، هم اجرا. اگر از قبل نصب کرده‌ای، می‌توانی منو را باز کنی و `[3] New tunnel - KHAREJ` را بزنی و فقط کد را paste کنی.

> PSK، پورت، پروتکل، IPها و subnet همه داخل Pair Code هستند. پس احتمال اینکه دو طرف تنظیمات متفاوتی داشته باشند وجود ندارد.

## ترنسپورت‌ها

| # | نوع | توضیح | پورت پیش‌فرض |
|---|---|---|---|
| 1 | **TCP Forward** | چند استریم روی یک اتصال رمزنگاری‌شده (smux)، reverse یا direct | 443 |
| - | **QUIC** | مالتی‌پلکس ذاتی روی TLS/UDP، بدون head-of-line blocking؛ روی خطی که UDP باز باشه قوی‌ترین و سریع‌ترین | 443 |
| 2 | **Tun · MDTprotocol** | تانل لایه ۳ روی پروتکل خام IP مثل GRE 47، ESP 50 یا هر عدد 1 تا 255 | — |
| 2 | **Tun · ICMP** | شبیه پینگ است. type و code قابل تنظیم‌اند | — |
| 2 | **Tun · TCP / UDP** | تانل لایه ۳ داخل TCP یا UDP رمزنگاری‌شده | 443 |
| 3 | **DNS** | تانل لایه ۳ روی بسته‌هایی که شکل DNS دارند | UDP 53 |
| 4 | **SSH** | TCP Forward روی سرور SSH داخلی برنامه، جدا از sshd خود سیستم | 2020 |

- **reverse:** ایران گوش می‌دهد و خارج به آن وصل می‌شود. وقتی خروجی ایران بسته است این حالت را انتخاب کن.
- **direct:** خارج گوش می‌دهد و ایران به آن وصل می‌شود. در این حالت پورت باید در فایروال خارج باز باشد.
- در حالت‌های Tun و DNS آدرس داخلی تانل‌ها `10.20.N.1` (ایران) و `10.20.N.2` (خارج) است. برای هر تانل یک N جدا خودکار انتخاب می‌شود.
- **فیلتر مسیر:** هر مسیر بعضی پروتکل‌ها را رد می‌کند و بعضی را نه. روی یک مسیر واقعی ایران به اروپا، پروتکل 47 (GRE) کاملاً بسته بود ولی 50 و 253 بدون افت کار می‌کردند؛ همان 47 بین دو سرور خارج سالم بود. اگر تانل وصل نشد یا در Status عدد `loss` بالا بود، یک پروتکل یا حالت دیگر را امتحان کن.
- **حالت DNS:** بعضی شبکه‌ها ترافیکی را که شکل DNS دارد محدود می‌کنند. روی یک خط دیتاسنتر ایران، بعد از حدود ۱۲ کوئری پشت‌سرهم جهت ایران به خارج قطع می‌شد. پس DNS را فقط وقتی انتخاب کن که بقیه‌ی حالت‌ها بسته‌اند، و پورت 53 را هم اگر جواب نداد عوض کن.
- **پورت کاربر:** `443` یعنی پورت 443 ایران به پورت 443 خارج می‌رود. `2083>8443` یعنی پورت 2083 ایران به پورت 8443 خارج می‌رود.

## پروفایل سرعت و تنظیمات

موقع ساخت تانل روی ایران یک **پروفایل سرعت** انتخاب می‌کنی:

- **Balanced:** پیش‌فرض، برای بیشتر خط‌ها خوبه.
- **Fast:** کانکشن موازی و بافر بیشتر؛ برای خط خوب و حداکثر سرعت (رم بیشتر).
- **Stable:** کانکشن کمتر و بافر کوچک؛ برای خط ضعیف و پر افت.
- **Advanced:** هر کدوم رو جدا تنظیم می‌کنی — تعداد کانکشن موازی، اندازه‌ی بافر، keepalive و کنترل ازدحام (bbr/cubic). هر سؤال پیش‌فرض داره، پس فقط Enter بزنی هم کار می‌کنه.

پروفایل داخل Pair Code می‌ره، پس هر دو طرف یکی می‌شن. بعداً هم از منوی `[4] Manage` ← `[8] Tuning` می‌شه عوضش کرد. پروفایل بیشترین اثر رو روی حالت‌های TCP Forward و SSH داره (کانکشن موازی + بافر).

## جعل IP مبدأ (Spoof) — فقط MDTprotocol

اگه مسیری ترافیک رو بر اساس IP فرستنده محدود می‌کنه، می‌تونی IP مبدأ بسته‌ها رو جعل کنی. موقع ساخت تانل MDTprotocol، جادوگر می‌پرسه و دو مقدار می‌خواد: IP جعلی سرور ایران و IP جعلی سرور خارج. این‌ها خودکار cross-pair می‌شن (SRC هر طرف = DST طرف مقابل) و داخل Pair Code می‌رن. بسته‌ها همچنان به IP واقعی طرف مقابل می‌رن؛ فقط آدرس فرستنده عوض می‌شه.

**هشدار:** بیشتر دیتاسنترها بسته با مبدأ جعلی رو بلاک می‌کنن و تانل بالا نمیاد. اول بدون spoof بساز، بعد اگه لازم شد روشنش کن. اسکریپت موقع روشن بودن spoof، reverse-path filter رو روی حالت loose می‌ذاره تا بسته‌ها رد نشن.

- **حالت QUIC:** روی UDP کار می‌کنه و مالتی‌پلکسینگ و TLS رو خودش داره، پس HOL blocking نداره و روی لینک پر افت بهتر از TCP عمل می‌کنه. فقط جایی کار می‌کنه که UDP باز باشه؛ اگه شبکه UDP رو ببنده، از TCP Forward استفاده کن. رمزنگاری و احراز هویت از PSK میاد (گواهی TLS به‌صورت قطعی از PSK ساخته می‌شه و دو طرف همدیگه رو pin می‌کنن).

## چک کردن

- منو ← `[4] Manage` ← `Status`. اگر تانل سالم باشد `running · connected` نشان می‌دهد.
- لاگ: `tail -f /var/log/max-dark-tunnel/<name>.log`. خط `tunnel is live` یعنی تانل وصل است و `TUNNEL IS DOWN` یعنی قطع است.
- در حالت‌های Tun و DNS: از سرور ایران `ping 10.20.N.2` بزن.
- در حالت‌های Tun و DNS، Status درصد افت بسته (`loss`) را هم نشان می‌دهد. تانلی که وصل است ولی افت بالایی دارد، عملاً ترافیک رد نمی‌کند.
- برای دیدن وضعیت همه‌ی تانل‌ها در یک خط: `maxdark --status`

## سرور ایران به گیت‌هاب دسترسی ندارد؟

- فایل `mdt-linux-amd64` را از بخش [Releases](https://github.com/darktunnelmika/max-dark-tunnel/releases) بگیر، در `/root/mdt` بگذار و از منوی `Core` گزینه‌ی `[2] Install from file` را بزن.
- یا یک mirror بساز و موقع نصب آدرسش را بده: `install.sh --mirror https://your.host/mdt`

## امکانات منو

وضعیت زنده، لاگ، ریستارت، ویرایش پورت‌ها بدون نیاز به pair دوباره، ریستارت زمان‌بندی‌شده (1h تا 24h)، داشبورد همه‌ی تانل‌ها، بهینه‌سازی شبکه (BBR)، باز کردن خودکار پورت در ufw، و آپدیت خودکار منو و هسته.

## امنیت

- رمزنگاری: ChaCha20-Poly1305. کلیدها با HKDF از PSK ساخته می‌شوند.
- در حالت‌های استریمی، هر اتصال کلید جدید و جداگانه برای هر جهت دارد.
- در حالت‌های بسته‌ای، کلید رفت و برگشت فرق دارد. به همین دلیل اگر بسته‌ای منعکس شود (مثلاً echo reply خود کرنل)، طرف مقابل نمی‌تواند بازش کند.
- کسی که PSK را ندارد چیزی جز ۳۲ بایت تصادفی دریافت نمی‌کند و اتصالش بسته می‌شود.
- کلید میزبان SSH از PSK ساخته می‌شود و سمت ایران آن را pin می‌کند. پس حمله‌ی MITM ممکن نیست.
